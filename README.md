# Cyberforteca 0.31 - Foundational Types

Public development version: **Cyberforteca 0.3**.
Internal implementation revision: **0.31**.

This additive reference package defines all twelve requested core types,
their invariants, future adapter interfaces, deterministic record serialization,
and an executable policy simulation. It uses Python 3.10+ and the standard
library, consistent with the available 0.2 excerpts. It has no Linux-specific
dependencies. The architecture contract, not Python, is the migration boundary.

**This is not production security software.** No hardware identity proof,
attestation verification, secure session handshake, credential verification,
encrypted transport, or actual resource enforcement is implemented. Test
fixtures explicitly supply simulated verification results. No successful
verifier stub is substituted for those missing systems.

## Run

From this directory:

```sh
python3 -m unittest discover -v
python3 -m examples.decisions
```

The example prints synthetic AUTHORIZED, RESTRICTED, DENIED, and recovery
decisions. Every example reports enforcement as NOT_ATTEMPTED. It uses only
synthetic references and contains no real personal or biological data.

## Review order

1. `docs/ARCHITECTURE.md`: normative contracts and authority boundaries.
2. `docs/PRESERVATION_02.md`: the available 0.2 review and migration rationale.
3. `cyberforteca/models.py`: types, enums, and construction-time invariants.
4. `cyberforteca/interfaces.py`: future adapter contracts.
5. `cyberforteca/simulation.py`: deliberately simulated policy evaluation.
6. `tests/test_boundaries.py`: security-boundary regression tests.
7. `docs/TEST_MATRIX.md`: requirements, evidence, and remaining limitations.

`examples/decisions.jsonl` and `examples/decisions.log` are reproducible snapshots
generated by the example. JSON is the complete structured representation.
The human-readable log is a concise projection, not an alternative authority.

## Preservation status

The two available 0.2 source documents were reviewed without modification.
They begin partway through the implementation, so this is an additive reference
package, not a claim that a complete 0.2 repository has been patched or regression
tested. Integration with the complete original source remains pending.

## Implemented versus specified

Implemented: immutable validated models, nominal ID separation, exact scope
matching, explicit policy fallbacks, recovery scope ceilings in the simulation,
structured decision projection, deterministic ASCII JSON, and boundary tests.

Specified only: secure provenance, device/app measurement verification, lifecycle
event handling, non-reusable session creation, protected grant registry,
grant revocation and enforcement, atomic policy snapshots, ownership verification,
persistent audit sequence allocation, and hash-chained audit storage.

No dependency on secrecy is assumed. The source, formats, decision rules, and
enforcement contracts are intended to remain understandable to an attacker.
